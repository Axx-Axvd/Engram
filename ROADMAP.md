# Engram — Roadmap & идеи развития

Живой документ с направлениями, куда можно двигать проект дальше. Не план на исполнение, а
«меню идей», к которому можно апеллировать при выборе следующего шага.

- Полный утверждённый план MVP и переработок: `C:\Users\PC\.claude\plans\cryptic-sniffing-russell.md`
- Текущее состояние: **MVP пройден** (M0–M6 + платформенный UI + переработка R1), всё на ветке `main`.

## Что уже работает (база)

- Документная модель: артефакты-документы по типам (Project brief / Requirements / User stories /
  Tasks / Test cases / Change request), внутри — структурированные **пункты** (R1, T1…) с
  перекрёстными ссылками; версии, журнал изменений, типизированные связи.
- Воркфлоу: **формализация** описания → 5 документов; **change request** → анализ влияния, новые
  версии, связи `changes`.
- Память и поиск: эмбеддинги + pgvector + обход графа (`/api/search/context`).
- **Проверка согласованности** (покрытие требований задачами/тестами, висячие ссылки и т.д.).
- Платформенный UI (Next.js): сайдбар-дерево, страницы документов с пунктами, граф, ручное
  создание/редактирование, формы формализации и change request, отчёт согласованности.
- LLM — детерминированный **mock** (текст шаблонный); вся обвязка реальная.

## 1. Сделать вывод по-настоящему умным (реальная LLM)

> Самый заметный для пользователя шаг: меняется только качество текста, структура остаётся.

- Реализовать `llm/anthropic.py` (и/или `llm/openai.py`) за существующим интерфейсом
  `LLMProvider`; переключение через `ENGRAM_LLM_PROVIDER` + ключ в `.env`. ⚠️ платные токены.
- Качественная **семантическая группировка по фичам** (сейчас мок группирует по «весомому» слову).
- Осмысленные требования/истории/задачи: объединение дублей, нормальные формулировки, разумное
  число пунктов.
- Реальные **эмбеддинги** для поиска (локальный `fastembed` уже опционален; облачные — для прода).
- Контроль стоимости: кэширование промптов, батчи, бюджеты токенов.

## 2. Уникальная фишка: AI-связывание и «умная память»

> То, чего нет у Confluence/Notion — ради этого проект и существует.

- **AI-подсказки связей**: эндпоинт `suggest-links` (эмбеддинги + LLM предлагают тип связи между
  артефактами) + UI принятия подсказок. *(было осознанно отложено)*
- **Точечный анализ влияния**: change request бьёт по конкретным пунктам (R3, R5), а не по всему
  документу; новые версии — на уровне пунктов.
- **Авто-починка согласованности**: LLM предлагает недостающую задачу/тест для непокрытого
  требования прямо из отчёта.
- Поиск **дубликатов и противоречий** между пунктами.
- Контекст-ретривер как продукт: отдавать «минимальный контекст» внешним агентам (см. §5 — MCP).

## 3. Глубина авторства и UX («ощущение платформы»)

- Редактирование **пунктов** в UI (добавить/править/переупорядочить), а не только `content`.
- Rich-text/Markdown-редактор; **комментарии и обсуждения** на артефактах.
- Граф получше: авто-раскладка (dagre/elk), фильтры, фокус на узле, рёбра на уровне пунктов.
- **Глобальный поиск** в UI по документам и пунктам (API уже есть).
- Тип **DecisionRecord** (запись о решении) из спецификации.
- Diff между версиями документа в UI.

## 4. Совместная работа и платформа

- **Аутентификация** + пользователи; роли и права доступа.
- **Несколько проектов/воркспейсов** (сейчас один неявный проект).
- Лента активности / журнал изменений в UI; уведомления.
- Реал-тайм обновления (WebSocket/SSE) при совместной работе.

## 5. Интеграции (открыть память наружу)

- **MCP-сервер** поверх Engram: отдавать релевантный контекст кодинг-агентам (Claude Code и т.п.) —
  изначальная идея «слой памяти для агентов».
- **Плагин/встраивание** в Confluence / Jira / Notion / GitHub (изначальная идея проекта как
  расширения существующих платформ).
- Импорт/экспорт: **Markdown-export**, позже **DOCX**; импорт из существующих документов/issue.

## 6. Оркестрация и масштаб

- **LangGraph** за `WorkflowEngine`: ветвление, чекпоинты, **human-in-the-loop** (утверждение
  предложений), стриминг. *(осознанно отложено, пока потоки процедурные)*
- Фоновые/асинхронные воркфлоу для больших проектов.
- Отдельный **графовый слой** (Neo4j), если запросы по связям перерастут SQL.

## 7. Надёжность и эксплуатация

- **CI**: тесты + ruff + build на push; pre-commit хуки.
- **Browser e2e** (Playwright) поверх текущего API-e2e.
- **Деплой**: Docker-образы api+web, прод-compose, управление окружением/секретами.
- **Запушить в git-remote** — сейчас удалёнка не настроена (`gh repo create`, аккаунт `Axx-Axvd`).
- Наблюдаемость: логи, метрики, трейсинг.
- Прод-безопасность: валидация входных данных, rate limiting, секреты.

## 8. Техдолг и уборка

- Переименовать каталог `upz-project` → `engram` (косметика).
- Полноценная установка **shadcn/ui** (сейчас компоненты на чистом Tailwind).
- **Версионирование на уровне пунктов** (сейчас на уровне документа).
- Больше тестов (сервисы, краевые случаи), фронтовые unit-тесты (Vitest).

## Приоритезация (impact × effort) — ориентир

| Идея | Польза | Трудозатраты | Когда |
|------|--------|--------------|-------|
| Реальная LLM (§1) | Очень высокая | Низкие | Сразу, как будет ключ |
| AI-подсказки связей (§2) | Высокая | Средние | Скоро (дифференциатор) |
| Редактирование пунктов в UI (§3) | Высокая | Средние | Скоро |
| MCP-сервер для агентов (§5) | Высокая | Средние | Стратегически важно |
| LangGraph + human-in-the-loop (§6) | Средняя | Средние | Когда нужен апрув-флоу |
| Аутентификация/воркспейсы (§4) | Средняя | Высокие | Перед мультипользовательностью |
| CI + деплой (§7) | Средняя | Низкие/средние | Перед публичным показом |
| Графовый слой Neo4j (§6) | Низкая (пока) | Высокие | Только при росте нагрузки |

Полная кодогенерация/SDLC, продвинутый MLOps, обязательная UML-генерация — из спецификации это
не цель MVP и ближайших итераций.
